# Контент

## 1. Принципы

- Весь пользовательский текст — **на русском**, живой и короткий, без канцелярита.
- Тон: уверенный, дружелюбный, без агрессивных продаж.
- Факты (IP, лимиты, расписание, наказания) должны совпадать с игровым сервером. При сомнении — уточняй у владельца проекта, не выдумывай.
- Один смысл — один блок. Не дублируй одинаковые преимущества в разных секциях.
- Заголовки — uppercase визуально (через CSS), в HTML пиши обычным регистром.

## 4. Правила

Четыре вкладки, порядок и количество:

1. **Основное** — 4 правила.
2. **Чат** — 5 правил.
3. **Игровой процесс** — 7 правил (по умолчанию активна).
4. **Проверки** — 4 правила.

Разметка:

```html
<li class="rule"><span>Текст правила</span></li>

<li class="rule rule--penalty">
  <span>Нарушение</span>
  <span class="rule__penalty">бан 30 дней</span>
</li>
```

Требования:

- Панели лежат в `#rulesPanels`, у каждой `role="tabpanel"`, `aria-labelledby`, `hidden` у неактивных.
- Вкладки — `button[role="tab"]` в `#ruleTabs`, `aria-controls`, `aria-selected`, `tabindex`.
- Не переноси текст правил в JS: это ломает SEO и просмотр без скриптов.
- Формулировки наказаний должны совпадать с реальной практикой сервера.

## 5. Обновления

Крупная строка:

```html
<article class="update-row" data-reveal>
  <div class="update-row__media">
    <img src="assets/img/updates/name.png" alt="..." width="..." height="..." loading="lazy" decoding="async">
  </div>
  <div class="update-row__text">
    <span class="update-row__num">04</span>
    <h3>Заголовок</h3>
    <p>Одно-два предложения.</p>
  </div>
</article>
```

Правила:

- Номер — сквозной, двузначный (`01`, `02`, …).
- Для портретного изображения добавь `update-row__media--portrait`.
- `width`/`height` обязательны: они резервируют место и предотвращают скачки layout.
- `alt` описывает пользу обновления, а не файл.
- Mini-card — без изображения, для мелких пунктов.

Текущие обновления: DLC на 9 видов построек, эмодзи в чате, рюкзаки, бустер FPS, хорошие плагины.

## 6. Отзывы

- Три блока `.review`, фон чередуется: `--dark`, `--deep`, `--light`.
- Внутри: `blockquote` (живой текст игрока), `review__nick`, ссылка на Steam.
- Не редактируй цитаты «для красоты» без согласования: это реальные отзывы.
- Не добавляй больше трёх без пересмотра сетки.

## 7. Скачивание

- Ссылка на лаунчер: `a.download-tile[data-download]`.
- `data-download` triggers счётчик `/api/launcher-download`.
- Шаги: Скачать → Установить → Запустить → Помощь.
- Системные требования — `<dl>` с парами `<dt>/<dd>`; на мобиле они становятся одноколоночными.
- Счётчик `#downloadsNum` обновляется с API; начальное значение — заглушка.

## 8. SEO и соцсети

В `<head>` лендинга:

- `title`, `description`, `canonical`;
- Open Graph (`og:title`, `og:description`, `og:image` = `assets/img/world/main.png`, 1920×1080);
- Twitter card;
- JSON-LD `WebSite` с `alternateName: WOOHRUST`;
- `theme-color: #05040c`.

При смене названия, описания или картинки обнови:

1. `index.html` (`title`, `description`, OG, JSON-LD).
2. `privacy/index.html` и `terms/index.html` (title/description/canonical).
3. `sitemap.xml` (даты/приоритеты, если нужно).
4. `robots.txt` — только если меняются правила индексации.

## 9. Юридические страницы

- `privacy/index.html` — политика конфиденциальности.
- `terms/index.html` — пользовательское соглашение.
- Обе страницы используют `assets/css/legal.css` и `assets/js/legal.js`.
- Ссылки в футере: `privacy/index.html`, `terms/index.html`.
- При добавлении новой юр. страницы: скопируй структуру, обнови canonical/title, добавь ссылку в футер и `sitemap.xml`.

## 10. Тексты, которые нельзя ломать

- «До вайпа · каждую пятницу в 16:00 МСК» — должно совпадать с `WIPE`.
- «Онлайн записывается каждые 5 минут. Время — МСК.» — описание графика.
- «Демо-график для предпросмотра…» — честная пометка при отсутствии API.
- «Проверки проходят только через Discord» — ключевое правило.
- «Покупки в магазине не дают преимущества в бою» — обещание честного доната.
