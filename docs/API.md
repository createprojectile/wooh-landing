# API

Сайт — статический frontend. Все запросы идут на тот же origin по путям `/api/*`. Backend в эту папку не входит.

На статическом хостинге без backend запросы дают **404** — это ожидаемое поведение, frontend переходит на fallback.

## 1. Эндпоинты

| Метод | Путь | Периодичность | Назначение |
| --- | --- | --- | --- |
| `GET` | `/api/servers` | каждые 10 с | Онлайн, очередь, лимит по серверам |
| `GET` | `/api/online-history?server=main&range=24h` | при загрузке и смене фильтра | История онлайна для графика |
| `POST` | `/api/visit` | при загрузке и каждые 60 с | Учёт визита, счётчик посетителей |
| `GET` | `/api/site-stats` | при загрузке и каждые 60 с | Скачивания и посетители за сутки |
| `POST` | `/api/launcher-download` | по клику на лаунчер | Счётчик скачиваний |

Все запросы `GET` идут с `cache: 'no-store'`.

## 2. `GET /api/servers`

Ответ — объект, ключи совпадают с `SERVERS[].id` (`main`, `combat`):

```json
{
  "main": {
    "success": true,
    "players": 150,
    "queued": 0,
    "maxPlayers": 200
  },
  "combat": {
    "success": true,
    "players": 24,
    "queued": 2,
    "maxPlayers": 50
  }
}
```

Поля:

| Поле | Тип | Обязательно | Комментарий |
| --- | --- | --- | --- |
| `success` | boolean | да | Если `false`, сервер пропускается |
| `players` | number | да | Всего игроков, включая очередь |
| `queued` | number | нет | Очередь; по умолчанию 0 |
| `maxPlayers` | number | нет | Если нет — берётся `max` из `config.js` |

Frontend показывает `players - queued` как «в игре», а очередь — отдельной подписью `+N в очереди`.

Если сервер отсутствует в ответе или `success !== true`, для него запускается публичный fallback.

## 3. `GET /api/online-history`

Query:

| Параметр | Значения |
| --- | --- |
| `server` | `main`, `combat` |
| `range` | `30d`, `14d`, `7d`, `3d`, `24h`, `12h`, `6h` |

Ответ:

```json
{
  "success": true,
  "points": [
    { "t": 1761302400000, "v": 142, "p": 168 },
    { "t": 1761302700000, "v": 151, "p": 171 }
  ]
}
```

| Поле | Тип | Комментарий |
| --- | --- | --- |
| `success` | boolean | Обязательно `true` |
| `points` | array | Нужно **минимум 3** точки |
| `t` | number | Unix timestamp в **миллисекундах** |
| `v` | number | Средний/текущий онлайн в точке |
| `p` | number | Пик в интервале; если нет — берётся `v` |

Требования:

- Точки должны идти по возрастанию `t`.
- Данные отображаются в московском времени (`Europe/Moscow`).
- Если точек меньше 3 или запрос упал, frontend рисует демо-график и показывает пометку.

Ожидаемая детализация: 5 минут. Для длинных диапазонов backend может агрегировать, отдавая `v` и `p` по бакетам.

## 4. `POST /api/visit`

Тело не требуется. Ответ:

```json
{
  "success": true,
  "downloads": 152,
  "visitors24h": 87
}
```

Используется для счётчика скачиваний и посетителей в футере. Если `visitors24h` нет — блок посетителей остаётся скрытым.

## 5. `GET /api/site-stats`

Тот же формат, что у `/api/visit`:

```json
{
  "success": true,
  "downloads": 152,
  "visitors24h": 87
}
```

Нужен, чтобы обновлять счётчики без инкремента визита.

## 6. `POST /api/launcher-download`

Вызывается при клике по `[data-download]`. Ответ — в формате статистики:

```json
{
  "success": true,
  "downloads": 153,
  "visitors24h": 87
}
```

Запрос отправляется с `keepalive: true`, чтобы успеть до перехода на скачивание.

## 7. Fallback-цепочка live-данных

```
1. GET /api/servers
2. GET https://api.gamemonitoring.ru/servers/{monitorId}
3. localStorage['wooh_live'] (TTL 10 минут)
4. DEMO_LIVE (main 128, combat 19)
```

Детали:

- Шаг 2 выполняется только для серверов, которых нет в ответе backend.
- Кэш используется только если **все** источники не дали данных.
- Кэш пишется после каждого успешного цикла.
- Демо-режим помечается в состоянии (`state.demo`), но в hero не показывается отдельным бейджем.
- Публичный монитор возвращает `response.status`, `response.numplayers`, `response.queueplayers`, `response.maxplayers`.

## 8. Ошибки и таймауты

- Любой non-2xx → исключение в `getJSON`, вызывающий код ловит и уходит в fallback.
- Нет явных таймаутов: используются браузерные значения `fetch`.
- Параллельные опросы live блокируются флагом `inFlight`.
- Ошибки счётчиков игнорируются молча.
- Ошибки графика приводят к демо-данным, а не к пустому экрану.

## 9. CORS и домены

- `/api/*` — same-origin, CORS не нужен.
- `api.gamemonitoring.ru` вызывается напрямую из браузера. Если монитор не отдаёт CORS-заголовки, fallback просто не сработает — сайт уйдёт в кэш/демо.
- Для продакшена надёжнее проксировать монитор через свой backend и отдавать данные в `/api/servers`.

## 10. Как проверить контракт локально

Создай временный mock (не коммить) или подними backend на том же порту. Минимальные проверки:

1. `/api/servers` возвращает оба ключа — hero показывает сумму, карточки — статусы.
2. `/api/online-history` с 10 точками — график без пометки «Демо».
3. `success: false` у одного сервера — второй продолжает работать.
4. Пустой `points` — появляется блок «Собираем данные»/демо-график.
5. `/api/visit` с `visitors24h: 1` — футер показывает «1 человек был».

## 11. Чего не делать

- Не менять названия полей без правки `live.js`, `chart.js`, `stats.js`.
- Не отдавать `players` строкой.
- Не отдавать `t` в секундах — график и подписи сломаются.
- Не кэшировать `/api/servers` на CDN: данные должны быть свежими.
- Не убирать демо-пометку: она честно сообщает, что данные ненастоящие.
